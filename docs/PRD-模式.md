# 模式（Modes）PRD

> 日期：2026-11-22　狀態：**規劃完成，還沒開始做**
> 一句話：把「用哪個引擎、要不要 AI 處理、用什麼提示詞、結果怎麼輸出」打包成一個個「模式」，可以用快捷鍵或依目前的 App 自動切換。
> 參考對象：VoiceInk 的 Modes。只參考功能結構，不照抄介面和文字。

---

## 1. 為什麼要做

現在 Scriber 只有三種固定的用法：聽寫、翻譯、說話改字。引擎、潤飾、標點都是全域設定，換情境就要進設定頁改。

使用者實際的需求是「不同場合要不同的處理」：
- 傳訊息：快、口語、短句不加句號。
- 寫信：正式一點，整理成段落。
- 寫程式的備註或對 AI 下指令：保留英文術語，不要潤飾。
- 問問題：把說的話當成問題，直接要 AI 的回答。

模式就是把這些組合存起來，一鍵切換，或依 App 自動套用。

現有的翻譯和說話改字，本質上就是兩個內建的模式。

## 2. 模式由什麼組成

| 區塊 | 欄位 | 說明 |
|---|---|---|
| 基本 | 名稱、圖示 | 圖示從一組 SF Symbols 裡選 |
| 觸發 | 快捷鍵 | 這個模式專用的快捷鍵（選填）。按了就用這個模式錄音 |
| | 自動套用的 App | 目前在這些 App 時自動用這個模式（macOS） |
| | 自動套用的網站 | 瀏覽器目前的網址符合時自動套用（macOS，見 7.2 的限制） |
| 辨識 | 引擎 | Scribe v3／Whisper／Turbo／自訂，或「跟隨預設」 |
| | 語言 | 自動／中文／英文… |
| | 即時顯示 | 只有 Scribe 可開 |
| | 文字格式 | 繁體、中英文空格、標點規則。可「跟隨全域設定」或各自覆寫 |
| AI 處理 | 開關 | 關的話只做規則式整理 |
| | 服務與模型 | Groq／Anthropic／自訂 OpenAI 相容，模型可選 |
| | 提示詞 | 從提示詞庫選，可編輯、可新增 |
| | 情境感知 | 把選取的文字、剪貼簿、目前 App 名稱提供給 AI（各自可開關） |
| 輸出 | 方式 | 貼上／回答／自訂指令（見第 4 節） |
| | 自動送出 | 貼上後自動按 Return、⌘Return 或不按 |
| | 設為預設 | 按一般快捷鍵時用的模式 |

## 3. 內建的模式

出廠就有，可以改、可以停用，不能刪到一個都不剩：

| 模式 | 引擎 | AI | 輸出 | 對應現在的功能 |
|---|---|---|---|---|
| **聽寫**（預設） | 跟隨預設 | 關 | 貼上 | 現在的一般聽寫 |
| **潤飾** | 跟隨預設 | 開，預設提示詞 | 貼上 | 現在的「AI 潤飾」開關 |
| **翻譯** | 跟隨預設 | 開，翻譯提示詞 | 貼上 | 現在的翻譯 |
| **改寫** | 跟隨預設 | 開，改寫提示詞，情境＝選取文字 | 取代選取文字 | 現在的說話改字 |
| **Email** | 跟隨預設 | 開，Email 提示詞 | 貼上 | 新。預設在 Mail 自動套用 |
| **助理** | 跟隨預設 | 開，助理提示詞 | 回答 | 新。說的話當成問題 |

「轉錄」（丟檔案進去）是獨立的頁面，不是模式，見 `PRD.md` §11 的檔案轉錄。

**遷移**：現有使用者的設定要無痛轉換。全域的引擎、潤飾開關、翻譯語言、說話改字和翻譯的修飾鍵，對應到上面的內建模式。升級後行為不變。

## 4. 輸出方式

| 方式 | 行為 |
|---|---|
| **貼上** | 打到游標位置（現在的做法） |
| **取代選取文字** | 用在改寫。沒有選取時等同貼上 |
| **回答** | 不打進輸入框。在浮動面板顯示 AI 的回答，可複製、可關閉 |
| **只複製** | 放進剪貼簿，不貼 |
| **自訂指令**（進階，預設隱藏） | 把結果交給一個 shell 指令或捷徑。見 7.4 的風險 |

---

## 5. 提示詞庫

- 內建幾個：預設（去贅字、整理標點）、Email、改寫、翻譯、助理、條列重點、會議紀錄。
- 使用者可以新增、編輯、複製、刪除。內建的可以「還原預設」。
- 提示詞裡可以用變數：`{{selected}}`（選取的文字）、`{{clipboard}}`、`{{app}}`、`{{language}}`（翻譯目標）。
- **安全規則不能被提示詞覆寫**：逐字稿永遠當成資料而不是指令；聽寫類的模式不回答內容；輸出只有結果。這些由程式在提示詞外層加上，使用者寫的部分只能調整風格和格式。「助理」模式例外，它本來就是要回答。
- 長度上限和輸出長度的估算沿用現在 `PolishPrompt` 的做法。

## 6. 介面

### 6.1 macOS
- 側邊欄新增 **模式**（在首頁下面）。
- 列表：每個模式一張卡，顯示圖示、名稱、開關、下面一排小標籤（引擎、語言、AI 模型、提示詞、觸發條件）。預設模式有標記。
- 右上角：新增、全域選項。
- 點一張卡開編輯面板，區塊照第 2 節的順序。原則跟現在的設定頁一樣：每列一個控制項、說明收進「?」、主色只給主要動作。
- 選單列：顯示目前模式，可手動切換。
- 浮動膠囊：錄音時顯示模式的圖示（現在翻譯和改字已經有）。

### 6.2 iOS
iOS 的限制比較多，做精簡版：
- 鍵盤**不知道目前是哪個 App**，所以沒有自動套用。
- 鍵盤上原本的翻譯鍵改成**模式鍵**：點一下在最近兩個模式間切換，長按浮出常用的三到四個模式（沿用現在翻譯語言選單的互動）。
- 「回答」輸出在鍵盤上沒有地方顯示：改成把回答打進輸入框，或在主 App 裡看。第一版 iOS 先不支援「回答」輸出。
- 主 App 的設定裡管理模式和提示詞。
- 沒有自訂指令。

## 7. 技術做法與限制

### 7.1 資料模型
- `DictationModeConfig`（可編碼的結構）和 `ModeStore`，放在共用套件，存在 App Group／Application Support 的 JSON。
- `PromptLibrary` 同上。
- `DictationRequest` 目前用 `mode: .dictate/.translate/.edit` 的列舉。改成帶一個模式的識別碼，管線依模式設定決定每一步。舊的三個值保留當相容層，對應到內建模式。
- 管線（`DictationPipeline`）改成吃一份「解析後的設定」：引擎、語言、是否 AI、提示詞、情境、後處理選項、輸出方式。現在散在 `AppSettings` 的欄位變成「全域預設」，模式可以覆寫。

### 7.2 自動套用（macOS）
- **依 App**：`NSWorkspace.shared.frontmostApplication` 的套件識別碼，按下快捷鍵那一刻判斷。可靠。
- **依網站**：要讀瀏覽器目前的網址。做法是輔助使用 API 讀網址列，或對 Safari／Chrome 用 AppleScript。兩者都依賴各瀏覽器的實作，Arc、Firefox 等不一定支援，而且 AppleScript 會多跳一個「允許控制」的授權。**第一版只做依 App，網站列為第二階段。**
- 衝突規則：模式專用快捷鍵 > 自動套用 > 預設模式。多個模式都符合同一個 App 時，取列表中較前面的。

### 7.3 模式專用快捷鍵
- 沿用現在的兩套機制：有輔助使用時用事件攔截（可以是單鍵或組合），沒有時用 Carbon 組合鍵。
- 現在的「Shift＋觸發鍵＝改字」「Control＋觸發鍵＝翻譯」變成改寫和翻譯兩個內建模式的預設快捷鍵。
- 要做衝突偵測：跟主快捷鍵、其他模式、系統快捷鍵重複時提示。

### 7.4 自訂指令的風險
- 把聽寫結果交給 shell 指令，等於讓「說出來的話」影響「執行什麼」。必須保證文字只當成參數或標準輸入傳入，**絕不能拼進指令字串**。
- 預設隱藏，要在進階選項打開。第一版可以不做，先列著。

### 7.5 自動送出
- 貼上後模擬按 Return。在聊天 App 很方便，但辨識錯了就直接送出去，沒有反悔的機會。
- 預設「不送出」。開啟時在設定裡用一行字提醒。

### 7.6 情境感知的隱私
- 選取的文字和剪貼簿內容會被送到 AI 服務。每一項都要是模式裡明確打開的開關，預設關閉（改寫模式的「選取文字」除外，那是它的功能本身）。
- 隱私權政策和首次設定的說明要更新。
- 診斷紀錄一樣不記內容，只記「帶了哪幾種情境、各多少字」。

### 7.7 「回答」輸出
- 用現在的浮動膠囊延伸成一個可以顯示多行、可捲動、可複製的面板。不搶焦點。
- AI 的回答用串流顯示比較好，但第一版可以先等整段回來再顯示。

## 8. 分階段

| 階段 | 內容 | 完成條件 |
|---|---|---|
| **M1 核心** | 資料模型、`ModeStore`、`PromptLibrary`、管線改成吃模式設定、舊設定遷移。行為不變 | 所有既有測試通過；升級後聽寫、翻譯、改字的結果跟之前一樣 |
| **M2 Mac 介面** | 模式頁、編輯面板、提示詞編輯、選單列切換、模式專用快捷鍵 | 可以新增一個自訂模式並用快捷鍵觸發 |
| **M3 自動套用與輸出** | 依 App 自動套用、回答面板、只複製、自動送出 | Email 模式在 Mail 自動生效；助理模式能顯示回答 |
| **M4 iOS** | 鍵盤的模式鍵、主 App 的模式管理 | 鍵盤上能切換模式 |
| **之後** | 依網站自動套用、自訂指令、AI 回答串流、模式匯入匯出 | — |

## 9. 要決定的事

1. **翻譯語言怎麼處理**：現在是「一個翻譯功能加三個常用語言」。改成模式後，是「翻譯」一個模式裡切語言（現在的做法），還是每個語言各一個模式？建議維持前者。
2. **iOS 鍵盤的翻譯鍵要不要改成模式鍵**：改了之後翻譯變成其中一個模式，多按一下。建議改，但保留長按直接選翻譯語言。
3. **自訂指令要不要做**：有安全風險，使用者也少。建議先不做。
4. **全域設定頁怎麼跟模式分工**：建議設定頁只留「預設值」和跟模式無關的東西（快捷鍵、音訊、權限、API key），其他搬到模式裡。

## 10. 目前同時在做的相關功能

這兩項已經派 agent 在做，不在這份 PRD 的範圍，但做模式時要接上：

- **檔案轉錄**：Mac 側邊欄的「轉錄」頁，丟音檔或影片進去，切段辨識，任意長度。之後可以讓轉錄也選模式（例如套用「會議紀錄」提示詞）。
- **音訊設定**（Mac）：選麥克風、開始和結束的提示音可自訂、錄音時靜音其他聲音、錄音時暫停媒體。
