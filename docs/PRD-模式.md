# 模式（Modes）PRD

> 日期：2026-11-22　狀態：**M1 核心、M2 Mac 介面、M3 自動套用與輸出、M4 iOS 完成**（M4：鍵盤的模式鍵、設定 → 模式；單元測試和模擬器截圖驗證過，**還沒在手機上按過**）。實作紀錄見第 11–14 節
> 一句話：把「用哪個引擎、要不要 AI 處理、用什麼提示詞、結果怎麼輸出」打包成一個個「模式」，可以用快捷鍵或依目前的 App 自動切換。
> 參考對象：VoiceInk 的 Modes。只參考功能結構，不照抄介面和文字。

---

## 1. 為什麼要做

現在 Scriber 只有三種固定的用法：聽寫、翻譯、說話改字。引擎、潤飾、標點都是全域設定，換情境就要進設定頁改。

使用者實際的需求是「不同場合要不同的處理」：
- 傳訊息：快、口語、短句不加句號。
- 寫信：正式一點，整理成段落。
- 寫程式的備註或對 AI 下指令：保留英文術語，不要潤飾。
- 問問題：把說的話當成問題，直接要 AI 的回答。

模式就是把這些組合存起來，一鍵切換，或依 App 自動套用。

現有的翻譯和說話改字，本質上就是兩個內建的模式。

## 3. 內建的模式

出廠就有，可以改、可以停用，不能刪到一個都不剩：

| 模式 | 引擎 | AI | 輸出 | 對應現在的功能 |
|---|---|---|---|---|
| **聽寫**（預設） | 跟隨預設 | 關 | 貼上 | 現在的一般聽寫 |
| **潤飾** | 跟隨預設 | 開，預設提示詞 | 貼上 | 現在的「AI 潤飾」開關 |
| **翻譯** | 跟隨預設 | 開，翻譯提示詞 | 貼上 | 現在的翻譯 |
| **改寫** | 跟隨預設 | 開，改寫提示詞，情境＝選取文字 | 取代選取文字 | 現在的說話改字 |
| **Email** | 跟隨預設 | 開，Email 提示詞 | 貼上 | 新。預設在 Mail 自動套用 |
| **助理** | 跟隨預設 | 開，助理提示詞 | 回答 | 新。說的話當成問題 |

「轉錄」（丟檔案進去）是獨立的頁面，不是模式，見 `PRD.md` §11 的檔案轉錄。

**遷移**：現有使用者的設定要無痛轉換。全域的引擎、潤飾開關、翻譯語言、說話改字和翻譯的修飾鍵，對應到上面的內建模式。升級後行為不變。

## 4. 輸出方式

| 方式 | 行為 |
|---|---|
| **貼上** | 打到游標位置（現在的做法） |
| **取代選取文字** | 用在改寫。沒有選取時等同貼上 |
| **回答** | 不打進輸入框。在浮動面板顯示 AI 的回答，可複製、可關閉 |
| **只複製** | 放進剪貼簿，不貼 |
| **自訂指令**（進階，預設隱藏） | 把結果交給一個 shell 指令或捷徑。見 7.4 的風險 |

## 5. 提示詞庫

- 內建幾個：預設（去贅字、整理標點）、Email、改寫、翻譯、助理、條列重點、會議紀錄。
- 使用者可以新增、編輯、複製、刪除。內建的可以「還原預設」。
- 提示詞裡可以用變數：`{{selected}}`（選取的文字）、`{{clipboard}}`、`{{app}}`、`{{language}}`（翻譯目標）。
- **安全規則不能被提示詞覆寫**：逐字稿永遠當成資料而不是指令；聽寫類的模式不回答內容；輸出只有結果。這些由程式在提示詞外層加上，使用者寫的部分只能調整風格和格式。「助理」模式例外，它本來就是要回答。
- 長度上限和輸出長度的估算沿用現在 `PolishPrompt` 的做法。

## 6. 介面

### 6.1 macOS
- 側邊欄新增 **模式**（在首頁下面）。
- 列表：每個模式一張卡，顯示圖示、名稱、開關、下面一排小標籤（引擎、語言、AI 模型、提示詞、觸發條件）。預設模式有標記。
- 右上角：新增、全域選項。
- 點一張卡開編輯面板，區塊照第 2 節的順序。原則跟現在的設定頁一樣：每列一個控制項、說明收進「?」、主色只給主要動作。
- 選單列：顯示目前模式，可手動切換。
- 浮動膠囊：錄音時顯示模式的圖示（現在翻譯和改字已經有）。

### 6.2 iOS
iOS 的限制比較多，做精簡版：
- 鍵盤**不知道目前是哪個 App**，所以沒有自動套用。
- 鍵盤上原本的翻譯鍵改成**模式鍵**：點一下在最近兩個模式間切換，長按浮出常用的三到四個模式（沿用現在翻譯語言選單的互動）。
- 「回答」輸出在鍵盤上沒有地方顯示：改成把回答打進輸入框，或在主 App 裡看。第一版 iOS 先不支援「回答」輸出。
- 主 App 的設定裡管理模式和提示詞。
- 沒有自訂指令。

## 7. 技術做法與限制

### 7.1 資料模型
- `DictationModeConfig`（可編碼的結構）和 `ModeStore`，放在共用套件，存在 App Group／Application Support 的 JSON。
- `PromptLibrary` 同上。
- `DictationRequest` 目前用 `mode: .dictate/.translate/.edit` 的列舉。改成帶一個模式的識別碼，管線依模式設定決定每一步。舊的三個值保留當相容層，對應到內建模式。
- 管線（`DictationPipeline`）改成吃一份「解析後的設定」：引擎、語言、是否 AI、提示詞、情境、後處理選項、輸出方式。現在散在 `AppSettings` 的欄位變成「全域預設」，模式可以覆寫。

### 7.2 自動套用（macOS）
- **依 App**：`NSWorkspace.shared.frontmostApplication` 的套件識別碼，按下快捷鍵那一刻判斷。可靠。
- **依網站**：要讀瀏覽器目前的網址。做法是輔助使用 API 讀網址列，或對 Safari／Chrome 用 AppleScript。兩者都依賴各瀏覽器的實作，Arc、Firefox 等不一定支援，而且 AppleScript 會多跳一個「允許控制」的授權。**第一版只做依 App，網站列為第二階段。**
- 衝突規則：模式專用快捷鍵 > 自動套用 > 預設模式。多個模式都符合同一個 App 時，取列表中較前面的。

### 7.3 模式專用快捷鍵
- 沿用現在的兩套機制：有輔助使用時用事件攔截（可以是單鍵或組合），沒有時用 Carbon 組合鍵。
- 現在的「Shift＋觸發鍵＝改字」「Control＋觸發鍵＝翻譯」變成改寫和翻譯兩個內建模式的預設快捷鍵。
- 要做衝突偵測：跟主快捷鍵、其他模式、系統快捷鍵重複時提示。

### 7.4 自訂指令的風險
- 把聽寫結果交給 shell 指令，等於讓「說出來的話」影響「執行什麼」。必須保證文字只當成參數或標準輸入傳入，**絕不能拼進指令字串**。
- 預設隱藏，要在進階選項打開。第一版可以不做，先列著。

### 7.5 自動送出
- 貼上後模擬按 Return。在聊天 App 很方便，但辨識錯了就直接送出去，沒有反悔的機會。
- 預設「不送出」。開啟時在設定裡用一行字提醒。

### 7.6 情境感知的隱私
- 選取的文字和剪貼簿內容會被送到 AI 服務。每一項都要是模式裡明確打開的開關，預設關閉（改寫模式的「選取文字」除外，那是它的功能本身）。
- 隱私權政策和首次設定的說明要更新。
- 診斷紀錄一樣不記內容，只記「帶了哪幾種情境、各多少字」。

### 7.7 「回答」輸出
- 用現在的浮動膠囊延伸成一個可以顯示多行、可捲動、可複製的面板。不搶焦點。
- AI 的回答用串流顯示比較好，但第一版可以先等整段回來再顯示。

## 9. 要決定的事

1. **翻譯語言怎麼處理**：現在是「一個翻譯功能加三個常用語言」。改成模式後，是「翻譯」一個模式裡切語言（現在的做法），還是每個語言各一個模式？建議維持前者。→ **已決定：維持一個翻譯模式，在模式裡切語言。**
2. **iOS 鍵盤的翻譯鍵要不要改成模式鍵**：改了之後翻譯變成其中一個模式，多按一下。建議改，但保留長按直接選翻譯語言。→ **已決定：改成模式鍵（M4 做）。**
3. **自訂指令要不要做**：有安全風險，使用者也少。建議先不做。→ **已決定：不做。**
4. **全域設定頁怎麼跟模式分工**：建議設定頁只留「預設值」和跟模式無關的東西（快捷鍵、音訊、權限、API key），其他搬到模式裡。→ **已決定：全域設定變成「預設值」，模式可以覆寫或「跟隨預設」。**

## 11. M1 實作紀錄（2026-11-22）

M1 只有核心，沒有任何介面，使用者看不到變化。三個 App 的呼叫方式幾乎沒改（`DictationRequest()`、`DictationRequest(mode: .translate)` 照舊能用）。

### 11.1 放在哪裡

| 東西 | 檔案 | 說明 |
|---|---|---|
| 資料模型 | `ScriberShared/Modes.swift` | `DictationModeConfig` 和它的各個區塊、`ModeOverride`、`PromptKind`、內建模式和提示詞的固定 id |
| 模式儲存 | `ScriberCore/Modes/ModeStore.swift` | `modes.json` |
| 提示詞庫 | `ScriberCore/Modes/PromptLibrary.swift`、`BuiltInPrompts.swift` | `prompts.json`，內建提示詞的文字在程式裡 |
| 解析 | `ScriberCore/Modes/ModeResolver.swift` | 模式＋全域預設值＋提示詞庫 → `ResolvedModeConfig` |
| 遷移 | `ScriberCore/Modes/ModeMigration.swift` | 只跑一次 |
| 管線 | `Polish/DictationPipeline.swift`、`Polish/PolishPrompt.swift` | 每次聽寫照 `ResolvedModeConfig` 走 |

兩個 JSON 跟字典、歷史一樣：iOS 在 App Group（鍵盤讀得到），Mac 在 `~/Library/Application Support/Scriber`。寫入是整檔原子替換、加跨行程檔案鎖；App 和鍵盤互相會收到「檔案變了」的通知。只讀的時候不會寫檔：沒有檔案就等於六個內建模式。

### 11.2 資料模型

`DictationModeConfig`（每筆都有 `version`，目前是 1）：
- 基本：`id`、`name`、`icon`（SF Symbol 名稱）、`isEnabled`、`isDefault`。
- `trigger`：`hotkey`（`ModeHotkey`：「按住某個修飾鍵再按主快捷鍵」或「一組按鍵」）、`appBundleIDs`、`websites`。**只存，不動作**。
- `recognition`：引擎、語言（`"auto"` 是自動偵測）、即時顯示。
- `textFormat`：繁體、中英文空格、標點規則、標點字數上限。
- `ai`：開關、服務、模型、提示詞 id、翻譯語言。
- `context`：選取文字、剪貼簿、App 名稱，各自開關，預設關。
- `output`：`paste`／`replaceSelection`／`answer`／`copyOnly`。沒有「自訂指令」。
- `autoSend`：`none`／`returnKey`／`commandReturn`。

「跟隨預設」用 `ModeOverride`：`.followDefault` 或 `.custom(值)`，存成值或 `null`。

讀檔很寬容：少的欄位用預設值；不認得的欄位忽略（下次寫入會被丟掉）；不認得的列舉值（例如之後新增的引擎）當成「跟隨預設」或安全的預設（輸出→貼上、提示詞類型→聽寫類）。只有沒有 `id` 的模式會被略過。

內建模式的 id 固定：`builtin.dictate`（聽寫）、`builtin.polish`（潤飾）、`builtin.translate`（翻譯）、`builtin.rewrite`（改寫）、`builtin.email`（Email，預設在 `com.apple.mail` 自動套用，但還沒動作）、`builtin.assistant`（助理）。

### 11.3 ModeStore 的規則
- 每次讀和寫都會修正成：六個內建模式都在、id 不重複、至少一個啟用、剛好一個預設且是啟用的。
- 內建模式可以改、停用、還原預設，**不能刪**（舊的 `.translate`／`.edit` 請求要靠它們）。自己建的可以刪。
- 停用到最後一個、刪掉最後一個啟用的模式：拒絕（`ModeStoreError.lastEnabledMode`），檔案不變。
- 停用預設模式：預設改回聽寫；聽寫也停用時，改成第一個啟用的模式。`setDefault` 會順便把那個模式打開。
- 檔案壞掉：搬到 `modes.corrupt-時間.json`，改用內建模式，不會當掉。檔案讀得出來但有幾筆模式讀不懂：先複製一份 `modes.unreadable-時間.json` 留著。
- 「最近用過」存在 App Group 的設定裡，給 iOS 的模式鍵用。

### 11.4 給 M2–M4 用的 API

```swift
// 模式
ModeStore.shared.modes                 // 可觀察，主執行緒
ModeStore.shared.snapshot() / mode(id:) / defaultMode / enabledModes
ModeStore.shared.add(_:) / update(_:) / delete(id:) / duplicate(id:)
ModeStore.shared.setEnabled(_:id:) / setDefault(id:) / restoreDefault(id:)
ModeStore.shared.move(fromOffsets:toOffset:) / reorder(ids:)
ModeStore.shared.noteUsed(id:) / recentModeIDs(limit: 2)   // iOS 模式鍵：最近兩個
ModeStore.shared.resolve(request)      // → ResolvedModeConfig

// 提示詞
PromptLibrary.shared.prompts / snapshot() / prompt(id:)
PromptLibrary.shared.add(name:kind:body:) / update(_:) / duplicate(id:) / delete(id:) / restoreBuiltIn(id:)
PromptTemplate.isBuiltIn / isModified

// 管線
DictationRequest(modeID: "…")           // 指定模式；不指定就照舊的 mode
pipeline.resolve(request)               // 先解析（例如決定要不要即時辨識）
pipeline.run(audioFile:request:resolved:) / run(transcript:request:resolved:sttMillis:)
PipelineResult.modeID / task / output / autoSend   // 給「回答」「只複製」「自動送出」用
RealtimeSTTSession.make(resolved:)      // 照模式的引擎和即時設定
```

`DictationRequest` 多了 `modeID`、`clipboardText`、`appName` 三個選填欄位（舊的請求照樣讀得懂）。剪貼簿和 App 名稱只能在模式有開對應的情境時才放進去：請求會短暫存在 App Group 裡做鍵盤和 App 之間的交接。

### 11.5 解析規則（模式 → 這次聽寫怎麼跑）
- 「跟隨預設」就用全域設定。
- 舊的請求：`.translate` → 翻譯，`.edit` → 改寫，`.dictate` → 預設模式（目前一定是聽寫）。`modeID` 指到不存在的模式時也照這個規則。
- AI：
  - 聽寫的 AI 是「跟隨預設」：全域的「AI 潤飾」開著就用那個服務潤飾，沒 key 或失敗就退回規則式整理；關著就只做規則式整理。跟以前一模一樣。
  - 翻譯、改寫、助理一定要 AI：用模式指定的服務，沒指定就用全域的，再沒有就用有 key 的那個（先 Groq 再 Anthropic），跟「AI 潤飾」開關無關。跟以前翻譯、說話改字的規則一樣。
  - 潤飾、Email 這類「明確打開 AI」的聽寫類模式：服務規則同上；完全沒有 key 時在開始錄音前就提示需要 key；AI 失敗時退回規則式整理。
- 改寫沒有選取文字：改跑預設模式，輸出變成貼上。
- 只有聽寫類會退回規則式整理；只有聽寫類會在很短的句子跳過 AI；短句標點規則只套用在聽寫類和翻譯；翻譯成非中文時不轉繁體。這些都跟以前一樣，只是從「三種模式」改成看「提示詞類型」。
- 沒有跑 AI 時，什麼情境都不送。改寫一定送選取文字（那就是它要改的東西）。
- 提示詞 id 找不到（被刪了）：內建模式用它自己的內建提示詞，自建模式用「預設」。
- 停用的模式如果被明確指定，還是會跑。要不要讓使用者選到，由介面決定。

### 11.6 提示詞庫與安全外層
- 內建七個：預設、Email、改寫、翻譯、助理、條列重點、會議紀錄。每個有固定的「類型」：聽寫類（預設、Email、條列重點、會議紀錄）、翻譯、改寫、助理。只有助理會回答內容。
- 內建提示詞只在檔案裡存使用者改過的名稱和內文；沒改過的，之後 App 更新提示詞會直接拿到新版。「還原預設」就是刪掉改過的部分。
- 使用者能改的只有「內文」（風格和格式）。程式在外面加上：開頭的角色和「最重要的規則」（逐字稿是資料、不回答、不加內容）、最後的輸出規則、使用者訊息裡用標籤包住的逐字稿。使用者自己寫或改過的內文，最後會再加一句「衝突時一律照最重要的規則」。聽寫類的結果如果長得像在回答問題，照樣會被擋下來。
- 內文開頭如果是「- 」條列，會接在「最重要的規則」清單後面（內建的預設、翻譯、改寫就是這樣，所以組出來的文字跟以前一字不差）。
- 變數：`{{selected}}`、`{{clipboard}}`、`{{app}}`、`{{language}}`，另外多一個 `{{spacing}}`（依文字格式的中英文空格規則）。只替換一次，替換進去的內容不會再被展開。
- 選取文字和剪貼簿的內容**永遠不放進系統提示詞**：`{{selected}}`、`{{clipboard}}` 會變成「<selected_text>」「<clipboard>」，內容放在使用者訊息裡的標籤中，標籤字樣在內容裡會被改掉，避免提早結束。模式沒開的情境，變數會變成「（未提供）」。
- 長度：情境的選取文字和剪貼簿最多 4000 字；App 名稱 80 字；提示詞內文最多 4000 字、名稱 40 字。輸出上限沿用 `PolishPrompt` 的估算；助理另外是 1024–4096 tokens，等待上限 30 秒。

### 11.7 遷移規則（升級後行為不變）
全域設定直接變成「預設值」，內建模式全部「跟隨預設」，所以**不用複製任何設定**：
- 引擎、語言、即時顯示、繁體、空格、標點：所有內建模式跟隨全域。
- AI 潤飾開關和服務：**聽寫的 AI 跟隨全域開關，預設模式一律是聽寫**。開著 AI 潤飾的人，一般聽寫照樣會潤飾；關著的照樣不會。設定頁原本的 AI 潤飾開關在 M1 照常有效。
- 翻譯語言和三個常用語言：翻譯模式跟隨全域的翻譯語言，鍵盤的語言鍵和 Mac 選單照舊在切它。
- Mac 的說話改字、翻譯修飾鍵：記到改寫、翻譯兩個模式的快捷鍵上（只存，目前還是由快捷鍵設定決定按鍵的作用）。在設定裡改修飾鍵時會同步更新。
- 只跑一次：App Group 設定裡的 `modes.migrationVersion`。iOS 在 App 啟動時跑，Mac 在 `DictationController.start()` 跑。

為什麼不是「AI 潤飾開著就把預設模式改成潤飾」：M1 還沒有模式介面，設定頁的 AI 潤飾開關還在。如果遷移時把預設改成潤飾，之後使用者在設定頁關掉 AI 潤飾，一般聽寫還是會潤飾，行為就變了。讓聽寫跟隨開關，開關在任何時候都照舊有效，M2 的介面上也只是「聽寫：AI 跟隨預設」，不會出現預設模式被偷偷換掉的情況。

### 11.8 延後或還沒動作的
- 模型欄位只存不用：Groq 目前的請求格式（`reasoning_effort` 等）是針對 gpt-oss，換模型要先處理各模型的格式（M2）。
- 「自訂 OpenAI 相容」的 AI 服務還沒有（`PolishProviderKind` 沒有這個選項）。
- 模式快捷鍵、依 App 自動套用、回答面板、只複製、自動送出：資料都有，程式還沒動作（M2、M3）。
- 情境：剪貼簿和 App 名稱要由 App 在開始錄音時讀取並放進請求，目前沒有任何地方會放（M2、M3）。
- Mac 選單的「翻譯」開關、iOS 鍵盤的翻譯鍵照舊（M2、M4）。
- 歷史紀錄還是只記舊的三種模式，沒有記模式 id。
- 新的提示詞（Email、條列重點、會議紀錄、助理）沒有用真的 AI 測過。

### 12.2 模式快捷鍵怎麼運作（`Mac/Engine/Logic/ModeHotkeys.swift`）
- **按住修飾鍵再按快捷鍵**：有輔助使用時由事件攔截判斷（`HotkeyStateMachine.routes`）；沒有時把修飾鍵加到主組合鍵上，用 Carbon 註冊（例如 ⌥⇧Space）。點一下／按住跟主快捷鍵的操作方式一樣。
- **自己的組合鍵**：不論有沒有輔助使用都用 Carbon 註冊（不需要權限，安全輸入時也有效），獨佔註冊；在設定裡錄快捷鍵時先放掉。點一下／按住同上；用它開始的錄音按兩次 esc 一樣能取消。
- 從 M2 起，改寫、翻譯的快捷鍵也由模式決定（`ModeStore`）。設定裡存的 `editModifier`／`translateModifier` 改成跟著模式同步（舊版 App 讀到的仍然正確），不再反過來寫進模式。
- 規則（`HotkeyRoutes.build`，跟以前的說話改字／翻譯相同）：改寫優先，再來翻譯，再照列表順序；同一組鍵只給第一個；停用的模式沒有快捷鍵；要讀選取文字的模式（改寫類提示詞）沒有輔助使用時不註冊在組合鍵上。
- **衝突**，在那一列用一句話寫出來（錄組合鍵時遇到就拒絕、繼續等）：
  - 跟快捷鍵是同一種鍵（⇧ 配右 ⇧）、組合鍵已經有 ⌥（⌥ 配 ⌥Space）、需要自動貼上；

### 12.3 按下去之後（`Mac/Engine/Logic/DictationStart.swift`）
- 主快捷鍵和選單的「開始聽寫」用**目前的模式**：「翻譯」鎖開著時是翻譯，否則是預設模式。
- 請求盡量保持以前的樣子：聽寫還是 `DictationRequest()`、翻譯 `DictationRequest(mode: .translate)`、說話改字 `DictationRequest(mode: .edit)`；只有舊的寫法選不到的模式才帶 `modeID`。
- 開始前的檢查改看模式本身：這個模式的引擎有沒有 key（以前只看全域引擎，跟隨預設時一樣）；一定要 AI 的模式沒有 Groq 或 Anthropic key 時不開麥克風、提示要 key；改寫類才讀選取文字；即時辨識照模式的引擎和設定（`RealtimeSTTSession.make(resolved:)`）。
- **目前的模式與「翻譯」鎖**：把翻譯設成目前的模式（選單或模式頁），就是打開以前選單的「翻譯」鎖（`mac.translateLocked`），預設模式不變；選其他模式時關掉鎖並設成預設。所以舊的「翻譯」開關行為完全一樣，包括「翻譯鎖開著、說話改字沒選取文字」時跑的還是預設模式（聽寫），不是翻譯。停用翻譯模式會關掉鎖。

### 14.2 哪些模式在鍵盤上、iOS 不支援的東西
- 鍵盤列出：**啟用的、提示詞不是改寫類的**模式。改寫類不列，因為選取文字時麥克風自動用「改寫」；列出來也只會在沒有選取時跑預設模式。
- **助理（「回答」輸出）：列在鍵盤上，回答直接打進輸入框。** iOS 沒有回答面板；打進去之後可以用復原鍵收回。（另一個做法是不列在鍵盤上，見 14.9。）設定頁的「結果」對它顯示「打到游標處」，檔案裡存的 `answer` 不動。
- **只複製**：結果放進剪貼簿，不打字，膠囊顯示「已複製」約 1.6 秒，沒有復原鍵。鍵盤只寫剪貼簿，**從不讀**。
- 自動送出：iOS 不做，模式設了也不動作，設定頁不顯示。
- 情境：鍵盤只在改寫時送選取的文字（就是以前的說話改字）；不讀剪貼簿，沒有 App 名稱。
- 依 App 自動套用、模式快捷鍵、自訂指令：iOS 沒有。

### 14.3 請求怎麼帶模式
- 鍵盤每次都帶 `modeID`：目前模式的 id，有選取文字時是 `builtin.rewrite`。舊的 `mode` 欄位照模式的類型填（翻譯類 `.translate`、改寫 `.edit`、其他 `.dictate`），只在模式剛好被刪掉時當後備。
- App 錄音（背景待命或跳 App）和鍵盤內錄音（實驗功能）用同一個請求。鍵盤內錄音檢查 key 時看的是**這個模式的引擎**，不是全域引擎。
- App 收到「停止」時保留 `modeID`（以前只會改 `mode`）；重試也一樣。
- 結果怎麼處理（打字或只複製）由鍵盤照請求自己解析（`ModeStore.keyboardDelivery`），鍵盤內錄音直接看結果的 `output`。

### 14.4 鍵盤讀模式（App Group）
- 有完整取用時，鍵盤出現、點或長按模式鍵、點麥克風時，讀 `modes.json`、`prompts.json`（檔案沒換就不重新解碼，只看檔案的修改時間）和 App Group 設定裡的「最近用過」，再加兩次 keychain 查詢（有沒有 Groq／Anthropic key）。鍵盤啟動時不做別的事。
- **沒有完整取用**：不讀（拿不到 App Group），鍵盤只顯示「開啟允許完整取用」，內部用內建模式。
- 檔案不存在、壞掉、部分讀不懂：照 `ModeStore` 原本的規則改用內建模式（壞檔搬到一旁、讀不懂的先複製一份）。「最近用過」裡已刪除、停用、或是改寫類的模式略過。
- 切換模式只寫「最近用過」（App Group 的 UserDefaults），**不寫 `modes.json`**。
- 反過來：App 裡改的模式，鍵盤下一次讀就生效；App 裡按「設為預設」時也寫「最近用過」，鍵盤會切到那個模式。App 裡麥克風（首頁試用）用預設模式，不會改鍵盤的目前模式。

### 14.5 設定 → 模式（App，`App/Features/Modes/`）
- 設定頁最上面一列「模式　N 個」（啟用的數量）。
- **模式列表**：灰底圓形圖示（不用主色，跟鍵盤一樣單色）、名稱、預設模式有「預設」標記，下面一行字：模式自己設的引擎和語言、AI 服務或「不用 AI」、提示詞（不是模式自己那個時才寫）、翻譯成哪種語言、只複製、已停用。改寫寫「選取文字時使用」。缺 AI key 時改成橘色的鑰匙圖示和「需要 AI 的 API key」；模式自己選的引擎缺 key 時寫那家的 key（跟隨預設的引擎缺 key 是首頁的設定步驟，不在每一列重複）。
  - 點一下編輯。長按選單：設為預設、複製、停用／啟用、還原預設（內建）或刪除（自訂）。左滑：停用／啟用、刪除（自訂）。
  - 右上「編輯」：拖曳排序、刪除自訂模式。「＋」：新增「新模式」（圖示星星，全部跟隨預設）並直接打開。
  - 至少要有一個啟用的模式：最後一個不能停用或刪除。
  - 「模式」標題旁的「?」：模式是什麼、模式鍵怎麼用（前 4 個、拖曳排順序）、改寫為什麼不在鍵盤上、預設是什麼。
  - 下面一列「提示詞　N 個」。
- **模式編輯**（推入，每個改動立刻存）：
  - 內建模式／自訂模式：名稱、圖示（36 個 SF Symbols 的格子，跟 Mac 同一組，選了自動返回）、啟用。
  - 辨識：引擎、語言（都有「跟隨預設（目前的值）」）。引擎缺 key 時橘色小字。
  - 文字格式：跟隨預設／自訂；自訂時才出現繁體、空格、標點、套用範圍。
  - AI 處理：AI 整理（只有整理文字類的提示詞）、服務、提示詞（推入選擇頁）、翻譯成（翻譯類）。「?」補一句「翻譯跟隨預設時，可以在鍵盤長按模式鍵直接選語言」。
  - 輸出：結果（打到游標處／只複製；改寫類是「取代選取的文字」）、預設模式（「是」或「設為預設」）。
  - 右上「…」：設為預設、複製成新模式、還原預設…（內建）或刪除…（自訂）。
  - **沒有放進 iOS 的**：快捷鍵、自動套用、情境、回答面板、自動送出、即時顯示、模型。這些值在檔案裡不動（iOS 和 Mac 的模式本來就分開存）。
- **提示詞**：
  - 列表：內建、自訂兩組；每個寫用途和被哪些模式用（名稱和用途一樣時不重複寫），改過的標「已修改」。點一下用 sheet 編輯；左滑還原（改過的內建）或刪除（自訂）；「＋」新增。
  - 模式的提示詞頁：打勾的是目前用的，點一下換；鉛筆編輯；最下面「新增提示詞」，建立後直接用在這個模式。
  - 編輯（sheet，取消／儲存）：名稱、用途（新增時，「?」說明四種用途）、內容（接近 4000 字時顯示字數）。內容的「?」寫可以用的變數（`{{language}}`、`{{spacing}}`、`{{selected}}`；`{{clipboard}}`、`{{app}}` 只有 Mac 有內容）和外面固定的安全規則。下面：複製成新的提示詞、還原預設（內建、改過時）或刪除提示詞（有模式在用時提醒會改用預設）。
- **設定頁原本的項目都留著**（它們就是預設值），沒有刪任何設定：引擎、輸出、標點的「?」補一句「這是預設值，模式可以各自改」；AI 潤飾寫明「聽寫」模式跟著它；翻譯的說明改成模式鍵的長按。

### 14.6 對既有使用者
- **沒碰模式鍵的人**：點一下照樣是翻譯開關，長按照樣看得到三個常用語言（全名），選了照樣切語言並打開翻譯。差別只有長按的膠囊多了模式。
- 其他差別：
  1. 選了的模式會記住，鍵盤重新載入後還在（以前翻譯會自己關掉）。
  2. 沒有 AI key 時長按照樣打開（AI 模式變淡），以前直接顯示「需要 API key」。
  3. 停用「改寫」後，選取文字不再改寫（以前沒有這個開關）。
  4. 設定頁多了「模式」。

### 14.7 診斷紀錄
- 鍵盤：`modes current=<id> partner=<id> menu=<數量> blocked=<數量> rewrite=<是否>`、`mode <id>→<id> via=tap|drag|popup-tap|voiceover`、`mode unavailable id=<id> reason=ai-key-missing`、`mode picker open options=<數量>`、`copy id=… len=<字數>`、點麥克風時的 `modeID`、鍵盤內錄音的 `modeID` 和 `output`。
- App：`cmd`、`pipe start` 多記 `modeID`；模式頁記 `mode added／deleted／default／enabled／reordered／prompt id=…`、`prompt saved id=… chars=<字數>`。
- 只記 id（內建 id 或 UUID）和數量；不記模式名稱、說的話、選取的文字、提示詞內容和 key。

### 14.9 要決定的事
1. **助理在鍵盤上**：現在列出來，回答打進輸入框。另一個做法是 iOS 不列「回答」的模式（PRD §6.2 原本寫第一版不支援）。
2. **記住目前的模式**：現在會記住。如果寧願每次鍵盤重新載入都回到聽寫（以前翻譯的做法），改一個地方就好。
3. **自訂的改寫類模式**不在鍵盤上，選取文字時一律用內建的「改寫」。
4. **鍵盤只列前 4 個**，照設定裡的順序。要不要另外給每個模式一個「顯示在鍵盤」開關。
5. **「設為預設」會把鍵盤切到那個模式**。
6. App Store 截圖 03（鍵盤翻譯語言）和 05（設定）跟現在的畫面不一樣了，要重截。
