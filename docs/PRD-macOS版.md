# Scriber macOS 版 PRD（v0.2）

> 日期：2026-11-22　狀態：**M0 + M1 第一版已實作，第三輪重新設計了首次設定、首頁和兩種快捷鍵；加了「模式」頁（模式 M2）**；可編譯、邏輯測試通過，畫面用離線截圖檢查過，還沒實機跑過。實作紀錄見第 11 節（以第 11 節為準）。
> 一句話：常駐在選單列，按快捷鍵說話，放開後把整理好的繁體中文文字打進目前游標所在的地方。

---

## 1. 目標與非目標

### 目標
1. 在 Mac 上任何 App 都能用快捷鍵聽寫。
2. 辨識和文字整理的結果跟 iOS 版一致（同一套核心）。
3. 跟 iOS 版放在同一個專案，共用核心程式碼。

### 非目標（第一版不做）
- 會議錄音、長時間錄音、轉檔案逐字稿
- 離線辨識（本機模型）
- iOS 和 Mac 之間同步字典和設定（列為之後的選項，見第 9 節）
- ~~即時串流辨識（邊說邊出字）~~：Mac 版已做（ElevenLabs Scribe v3 Live），見第 11 節「即時辨識」

---

## 2. 跟 iOS 版的差別

| | iOS | macOS |
|---|---|---|
| 入口 | 第三方鍵盤 | 選單列常駐 + 全域快捷鍵 |
| 錄音 | 鍵盤不能錄，要靠主 App 在背景錄 | App 自己直接錄 |
| 輸入文字 | 鍵盤的 `textDocumentProxy` | 模擬貼上（需要輔助使用權限） |
| 知道目前是哪個 App | 做不到（公開 API 沒有） | 做得到（`NSWorkspace.frontmostApplication`） |
| 跳 App、背景待命、橘燈 | 最大的難題 | 不存在 |
| 需要的權限 | 麥克風、完整取用 | 麥克風、輔助使用 |

iOS 版花最多時間的部分（鍵盤和主 App 的通訊、背景待命、自動跳回）在 Mac 上全部用不到。

## 3. 可以共用什麼

### 3.1 直接共用（已經能在 macOS 編譯和測試）
`Packages/ScriberCore` 當初就寫成只依賴 Foundation：

- `STT/`：Scribe v3、Groq Whisper、自訂 OpenAI 相容引擎
- `Polish/`：AI 潤飾、規則式清理、整條處理流程 `DictationPipeline`
- `ZhTW/`：簡轉繁（OpenCC 字典）、標點與中英文空格
- `Stores/`：個人字典、歷史紀錄、Keychain
- `Audio/`：PCM 重新取樣、WAV 寫檔
- `ScriberShared`：設定、翻譯語言清單、使用統計、診斷紀錄

### 3.2 大部分可沿用，要調整版面
主 App 的 SwiftUI 畫面：字典、歷史、設定、API key、自訂引擎、首頁的統計卡。
- 需要改：導覽結構（Mac 用側邊欄或分頁視窗，不是底部分頁列）、`UIKit` 相關的小地方（觸覺回饋、`UIApplication.open`、顏色名稱）。

### 3.3 不能共用
- `Keyboard/` 整個資料夾
- `App/Engine/` 裡跟 iOS 音訊工作階段、背景待命、鍵盤通訊有關的部分（`AVAudioSession` 在 macOS 不存在）
- 首次設定流程（Mac 的權限和步驟不同）

### 3.4 要注意的共用細節
- **App Group**：iOS 用 `group.com.geekaz.Scriber` 存設定和檔案。Mac 版只有一個程序，不需要 App Group，但 `AppGroup.containerURL` 和 `AppGroup.defaults` 要在 macOS 上給一個合理的位置（Application Support 和標準 UserDefaults）。
- **Keychain 群組**：iOS 版用共用群組讓鍵盤讀得到 key。Mac 版用一般的 Keychain 就好。

## 4. 使用流程

1. Scriber 常駐在選單列，沒有 Dock 圖示。
2. 使用者把游標放在任何輸入框。
3. **按下快捷鍵**開始錄音，螢幕上出現一個小浮動指示（波形），選單列圖示變色。
4. **再按一次**（或放開，視模式而定）結束。
5. 浮動指示顯示處理中，完成後文字出現在游標位置。
6. 失敗時浮動指示顯示簡短原因，文字同時留在歷史紀錄，可以從選單列複製。

### 觸發模式（設定可選）
- **點一下開始、再點一下結束**（預設，跟 iOS 一致）
- **按住說話、放開送出**

### 快捷鍵（第三輪定案，見 11 節）
- **組合鍵**（預設 ⌥ Space）：不需要任何權限，裝好馬上能用；結果放進剪貼簿，按 ⌘V 貼上。
- **單鍵**（預設右邊的 Option 單獨按）：打開「自動貼上」（輔助使用權限）後自動改用，說完直接貼上。
- 另外提供：按住時加按另一個鍵進入翻譯模式；有選取文字時觸發「說話改字」（需要自動貼上）。

## 5. 功能需求

### 5.1 核心
- 全域快捷鍵聽寫，支援兩種觸發模式
- 把文字插入目前的 App
- 取消（按 Esc）
- 個人字典、歷史紀錄、三種辨識引擎加自訂引擎、選配的 AI 潤飾
- 一律輸出繁體、一律用「台」

### 5.2 Mac 才做得到的
- **依 App 調整語氣**：知道目前在哪個 App，可以讓使用者為不同 App 設定語氣（例如 Slack 隨意、Mail 正式）。需要開 AI 潤飾。
- **說話改字**：讀取目前選取的文字，用說的下指令改寫，結果取代選取範圍。
- **翻譯模式**：同 iOS，三個常用語言快速切換。

### 5.3 介面
- **選單列選單**：目前狀態、最近幾筆結果（點一下複製）、切換引擎、開啟主視窗、結束。
- **浮動指示**：靠近螢幕底部中央的小膠囊，風格跟 iOS 鍵盤的麥克風膠囊一致（黑白、波形、紅點）。不搶焦點。
- **主視窗**：首頁（省下的時間）、字典、歷史、設定。沿用 iOS 的設計語言。
- **首次設定**：歡迎 → 麥克風 → API key → 試一次（用組合鍵，不需要輔助使用）→ 開啟自動貼上（選用，可以之後再做）。見 11 節第三輪。

### 5.4 非功能需求
| 項目 | 目標 |
|---|---|
| 延遲 | 10 秒語音，結束到文字出現 ≤ 1.5 秒（跟 iOS 同一個目標） |
| 資源 | 閒置時不佔用麥克風，CPU 接近 0 |
| 隱私 | 音檔辨識完就刪；歷史只存本機；不做分析追蹤 |
| 系統版本 | macOS 14 以上（跟核心套件目前宣告的版本一致） |

## 6. 技術做法

### 6.1 專案結構
在同一個 XcodeGen 專案加一個 macOS target：

```
Scriber/
├── App/                    # iOS 主 App
├── Keyboard/               # iOS 鍵盤
├── Mac/                    # macOS App（新增）
│   ├── App/                # 進入點、選單列
│   ├── Engine/             # 錄音、快捷鍵、插入文字
│   ├── Features/           # Mac 專屬畫面（首次設定、浮動指示）
│   └── UI/
├── Shared/                 # iOS 和 Mac 共用的 SwiftUI 畫面（從 App/Features 搬過來）
└── Packages/ScriberCore/   # 核心，已共用
```

`App/Features` 裡可共用的畫面要先搬到 `Shared/`，把 `UIKit` 相依的部分用 `#if os(iOS)` 隔開或抽成小的平台介面。這一步會動到 iOS 版，所以排在 iOS 版穩定之後。

### 6.2 錄音
- `AVAudioEngine` 的輸入節點，轉成 16 kHz 單聲道，寫成 AAC 或 WAV。
- macOS 沒有 `AVAudioSession`，不需要設定類別，也沒有背景限制。
- 只在錄音期間啟動引擎，閒置時不碰麥克風。
- 可沿用 iOS 的 `CaptureBuffer`（要確認它沒有 iOS 專屬的相依）和核心的 `PCMCapture`。

### 6.3 全域快捷鍵
兩種做法，要在實作時擇一並驗證：

| 做法 | 能做什麼 | 限制 |
|---|---|---|
| Carbon 的 `RegisterEventHotKey` | 一般的組合鍵（例如 ⌥Space） | 不能偵測單獨按修飾鍵（Fn、右 Option） |
| `CGEventTap` | 任何按鍵，包含單獨的修飾鍵、按住和放開 | 需要輔助使用（或輸入監控）權限；沙盒內受限 |

要支援「按住右 Option」這種操作，需要 `CGEventTap`。

### 6.4 把文字插入目前的 App
- **主要做法：模擬貼上。** 把結果放進剪貼簿 → 送出 ⌘V 的鍵盤事件 → 短暫延遲後還原原本的剪貼簿內容。
  - 需要輔助使用權限。
  - 要處理：還原剪貼簿的時機、剪貼簿管理工具會記到這一筆（可加上標記讓常見工具忽略）、密碼欄位等安全輸入狀態下會失敗。
- **備援：直接送出文字的鍵盤事件。** 不動剪貼簿，但長文字慢，部分 App 對中文支援不佳。
- **說話改字**需要讀取選取文字：用輔助使用 API 讀，或模擬 ⌘C。兩種都要輔助使用權限。

### 6.5 依 App 調整語氣
- `NSWorkspace.shared.frontmostApplication` 取得目前 App 的識別碼。
- 設定裡維護一張「App → 語氣」的表，帶進 `PolishContext`。目前 `PolishContext` 只有 `fieldHint`，要加一個欄位。

### 6.6 選單列與浮動指示
- SwiftUI 的 `MenuBarExtra`。
- `LSUIElement` 設為 true，不顯示 Dock 圖示。
- 浮動指示用不搶焦點的 `NSPanel`（焦點留在使用者正在打字的 App，否則貼上會貼錯地方）。

## 7. 發行方式（要先決定）

這會影響技術做法和收費，要在開工前定案。

| | Mac App Store | 自己的網站直接發行 |
|---|---|---|
| 沙盒 | 必須 | 不需要 |
| 全域快捷鍵（單獨修飾鍵）、模擬貼上 | 沙盒內受限，可能做不到或被退件 | 可以 |
| 上架條件 | 審核 | Developer ID 簽署 + Apple 公證 |
| 收費 | App Store 買斷，跟 iOS 一樣方便 | 要自己處理金流和授權碼 |
| 更新 | App Store | 要自己做（例如 Sparkle） |

**初步判斷**：這類工具（VoiceInk、Wispr Flow、Typeless 的 Mac 版）多半是直接發行，因為需要的系統權限跟沙盒衝突。但這是依一般情況的判斷，沒有針對 Scriber 的做法實際驗證過沙盒內能做到哪裡。開工前要先做一個小實驗確認。

如果走直接發行，「一次買斷 60 元」的收費方式要另外設計（金流、授權驗證，或乾脆免費當作 iOS 版的搭配）。

## 8. 風險

| 風險 | 說明 |
|---|---|
| 輔助使用權限的引導 | 使用者要手動到系統設定打開，是流失的主要關卡。引導畫面要做好 |
| 模擬貼上不是每個 App 都行 | 終端機、遠端桌面、部分 Electron App、安全輸入欄位可能失敗。要有備援和清楚的失敗提示 |
| 剪貼簿被覆蓋 | 還原時機不對會讓使用者原本複製的東西不見 |
| 沙盒相容性 | 見第 7 節 |
| 已有成熟的競品 | Kazen 自己在用 VoiceInk。Scriber Mac 版的差異是繁中優化、跟 iOS 一致的字典與設定 |
| 共用畫面的重構會動到 iOS 版 | 所以排在 iOS 版穩定之後 |

## 11. 更新紀錄（實際做成的樣子，以這一節為準）

### 2026-11-22　M0 + M1 第一版

#### 已定案（不再討論）
| 項目 | 決定 |
|---|---|
| 發行方式 | **先直接發行，不開沙盒**（沒有 App Sandbox entitlement）；開 hardened runtime；用 `project.yml` 的團隊 `77T9U5NPX9` 簽署。Mac App Store 之後再評估。 |
| 觸發方式 | 預設**點一下開始、再點一下結束**（跟 iOS 一致），可改成「按住說話」。 |
| 預設快捷鍵 | **右邊的 Option 單獨按**，可改成右 Command、右 Control、Fn／🌐。 |
| 後端與 key | 沒有後端，用使用者自己的 key；AI 潤飾預設關閉；一律輸出繁體、一律用「台」（沿用核心流程）。 |
| 翻譯、說話改字 | 只要有 Groq 或 Anthropic 的 key 就能用，不需要打開 AI 潤飾（核心流程本來就這樣處理）。 |
| 最低系統版本 | macOS 14。 |

#### 做了什麼
- **Target**：`ScriberMac`（`com.geekaz.Scriber.mac`，產物 `Scriber.app`，`LSUIElement`，沒有 Dock 圖示），原始碼在 `Mac/`，連結 `ScriberCore` + `ScriberShared`。另有 `ScriberMacTests`（不掛 App 的邏輯測試）。iOS 兩個 target 沒動。
- **核心套件的 macOS 調整**（`#if os(macOS)`，iOS 行為不變）：
  - `AppGroup.containerURL` → `~/Library/Application Support/Scriber`；`AppGroup.defaults` → 標準 `UserDefaults`。`swift test` 這類非 App 程序改用暫存資料夾，不會寫進 App 的資料。
  - `KeychainStore` 在 macOS 不用共用群組，存在登入鑰匙圈的一般項目。
- **錄音**：每次錄音才建立 `AVAudioEngine`，結束就釋放，閒置不碰麥克風。輸入轉成 16 kHz 單聲道（沿用核心的 `StreamingResampler`，包在可測試的 `ClipWriter`；第二輪改成 AAC，見下方）。錄音中換裝置或拔掉麥克風：重建引擎、接著寫同一個檔；接不回來就用已錄的內容結束。少於 0.3 秒或峰值低於 0.12 直接丟掉（跟 iOS 同門檻）。最長 15 分鐘（第二輪調整）。辨識完刪檔，網路／伺服器錯誤時保留音檔可重試。
- **全域快捷鍵**：`CGEventTap`（需要輔助使用權限），跑在自己的執行緒。只有「乾淨的單按」才算：按下時沒有其他鍵、放開前沒按其他鍵或滑鼠；⌥E、⌥點擊這類組合完全不受影響，事件也不會被吞。只有錄音中的 Esc 會被吞掉（用來取消）。系統停用 tap 時馬上重新啟用，每 2 秒再檢查一次；權限打開後自動建立 tap，不用重開（建立失敗才請使用者重新開啟）。
  - 變化：按住 **Shift** 再按快捷鍵 = 說話改字；按住 **Control** = 翻譯。兩個都可以在設定改。
  - 點一下模式：按超過 0.8 秒不算開始（避免按著 ⌥ 看選單時誤觸）；結束時不限長度。
  - 按住模式：按住 0.2 秒以上才開始錄音，快速的 ⌥ 組合不會碰到麥克風；按住期間按了其他鍵就靜靜取消。
- **貼上**：把文字放上剪貼簿（加上 `org.nspasteboard.TransientType`、`ConcealedType`、`AutoGeneratedType`、`source` 標記，剪貼簿管理工具會忽略），等修飾鍵放開，送出 ⌘V（依目前鍵盤配置找出 V 的鍵碼），0.6 秒後把原本剪貼簿的**所有項目、所有型別**放回去；期間如果有人改過剪貼簿就不還原。連續兩次聽寫時沿用第一次的原始內容。沒有輔助使用權限、或有 App 開著安全輸入時不貼，改成一般複製並顯示「已複製，請按 ⌘V」；選單的「複製上一段」永遠拿得到最近的結果。
- **說話改字**：先用輔助使用 API 讀選取文字（沒有副作用）；讀不到才用 ⌘C 備援（借用剪貼簿、讀完放回）。沒有選取就當一般聽寫。結果貼上取代選取範圍。
- **翻譯**：快捷鍵變化，或選單裡的「翻譯模式」開關；選單可在三個常用語言間切換。
- **介面**：
  - 選單列圖示（SF Symbol 範本圖）：待命 `mic`、錄音 `mic.fill`、處理中 `ellipsis.circle`、需要處理 `mic.slash`、剛出錯 `exclamationmark.circle`。選單：狀態、開始聽寫、取消、重試上一段、複製上一段、最近 5 筆（點一下複製）、翻譯模式與語言、辨識引擎、AI 潤飾、設定…、結束。
  - 浮動指示：不搶焦點、不能成為 key window 的 `NSPanel`，在目前工作的螢幕底部中央。黑白膠囊＋紅點＋即時波形；處理中轉圈；錯誤顯示圖示加短字，自動消失。平常滑鼠可以穿過；只有「重試」和「去設定」的訊息可以點。

### 2026-11-22　第三輪：即時辨識（邊說邊出字，ElevenLabs Scribe v3 Live）

設定「即時顯示文字」打開、辨識引擎是 ElevenLabs Scribe、而且有 ElevenLabs 的 key 時，說話的同時就把聲音串流到 Scribe v3 Live，浮動指示即時顯示辨識到的字；放開（或再按一次）後，把即時辨識的最終文字交給跟平常一樣的整理流程再貼上。其他情況完全照舊。

#### 怎麼運作
- **錄音照舊**：每次錄音一樣寫 16 kHz 的 AAC 檔。即時辨識拿的是同一份聲音：`ClipWriter` 每寫進檔案一段 16 kHz 樣本，就同時交給 `RealtimeSTTSession`（含停止時重新取樣器吐出的最後一小段），所以串流和備用的錄音檔內容完全相同；錄音中換麥克風也一樣接得上。
- **連線**：按下快捷鍵就開始連線（約 0.3 秒，跟麥克風啟動同時進行）。連線完成前錄到的聲音先存著（最多 12 秒），連上後一次送出。
- **協定**（`Packages/ScriberCore/Sources/ScriberCore/STT/RealtimeSTTWire.swift`，每個非顯而易見的地方都附了文件出處）：
  - `wss://api.elevenlabs.io/v1/speech-to-text/realtime`，key 放在 `xi-api-key` 標頭；設定全部是網址參數：`model_id=scribe_v3_live`、`audio_format=pcm_16000`、`commit_strategy=manual`、`language_code=zh`、`secondary_languages=en`、`no_verbatim=true`、個人字典的詞用重複的 `keyterms=`（最多 50 個、合計 1000 字；超過 50 個的放進第一段聲音訊息的 `keyterm_library`）。
  - 聲音：JSON 文字訊息 `{"message_type":"input_audio_chunk","audio_base_64":…,"commit":false,"sample_rate":16000}`，16-bit 單聲道 PCM，每段 0.2 秒。
  - 結束一段（commit）：同樣的訊息、聲音是空字串、`"commit":true`（跟官方 SDK 的 `commit()` 一樣）。
  - 伺服器回 `partial_transcript`（說話中、會一直改的文字）和 `committed_transcript`（一段的最終文字，每次 commit 回一個）。
- **分段**：說超過 20 秒後，在下一個停頓處送一次 commit；連續說到 30 秒就直接送。原因：伺服器在約 36 秒沒 commit 時會自己切一段（實測確認），而且官方建議每 20–30 秒 commit 一次。這樣每個 commit 都對得上一個回覆，停止時才知道最後一段到了沒有。
- **停止**：送出剩下的聲音和最後一次 commit，等最後一段的 `committed_transcript`。最後一段沒有聲音、也沒辨識出字時不送 commit；不到 0.3 秒時先補一點靜音（伺服器規定至少 0.3 秒，不足會直接斷線，實測確認）。
- **最終文字和畫面上的字**：畫面上顯示的是原始辨識結果，只先做「簡轉繁＋台」（Scribe 對中文輸出簡體，實測確認；每次更新約 0.3 毫秒）。真正貼上的是所有 `committed_transcript` 接起來的文字，再經過跟上傳辨識**完全相同**的後段（AI 潤飾或規則式清理 → 個人字典 → 繁體＋台 → 標點與中英文空格），用的是新的 `DictationPipeline.run(transcript:request:sttMillis:)`，跟原本的 `run(audioFile:request:)` 共用同一段程式。所以貼上的字可能跟最後看到的不完全一樣（例如潤飾過、字典改過、標點變全形）。
- **翻譯、說話改字**：一樣邊說邊顯示（顯示的是說出來的原文），貼上的結果照舊由 AI 產生。

#### 什麼時候改用一般辨識（上傳錄音檔）
出現下列任何一種情況，就用已經錄好的檔案走原本的上傳辨識，使用者一樣拿得到文字；**兩條路只有一條會產生貼上的文字，不會重複**：
- 連不上、5 秒內沒有 `session_started`、key 被拒（`auth_error`）、參數被拒（`invalid_request`）等任何伺服器錯誤
- 錄到一半斷線、伺服器關閉連線、送不出去（4 秒內送不出 → 判定卡住，不會無限制地堆積聲音）
- 停止後最後一段 3 秒內沒回來（整個收尾最多 8 秒）
- 即時辨識的最終文字是空的
- 連續 3 次即時辨識失敗後，接下來 10 分鐘直接用一般辨識（避免協定有變時每次都多等一次逾時）

按 Esc 或取消時直接關閉連線，不會改用一般辨識。用哪一條路、為什麼，都會寫進診斷紀錄。

#### 浮動指示
即時模式錄音時，膠囊在第一個字出來時長成一個小面板：上方一樣是紅點、模式標記和波形，下方是最近一兩行字，新的字在最後；字比兩行多時，舊的往上移出去，最上面一行淡出。還在辨識中的那段字顏色淡一點，定案後變成實色。面板只在第一次出字時變大一次，之後大小固定；已定案的部分只在新的一段定案時才變，所以說話中只有最後的字在動，不會整段跳動。不搶焦點；「減少動態效果」打開時不做縮放、不晃動。即時辨識中途失敗就縮回一般膠囊。非即時模式完全照舊。錯誤訊息沿用原本的短字。

#### 實機驗證（2026-11-22，用 Kazen 提供的 key，只用 `say` 產生的合成語音檔，沒有開麥克風或 App）
- **已實際打過 API 確認**：連線方式與標頭、全部網址參數（伺服器在 `session_started` 回顯了 `language_code`、`secondary_languages`、`keyterms`、`no_verbatim`）、聲音與 commit 訊息格式、`partial_transcript`（含 `turn_probability`）和 `committed_transcript` 的欄位、一次 commit 一個回覆（靜音段回空字串）、連線中一次送出 10 秒（每段 1 秒或 5 秒）都可以、約 36 秒自動 commit、commit 不足 0.3 秒會 `commit_throttled` 並斷線、0.35 秒可以、超過 50 個 keyterms 會 `invalid_request`（關閉碼 1008）、32 個字的 keyterm 可以、錯的 key 是升級成功（101）後送 `auth_error` 再關閉（1000）、15 秒沒有任何訊息伺服器會關閉（1000）、`keyterm_library` 和 `multilang_mode` 都被接受、不是 JSON 的訊息回 `input_error` 但不斷線、25 秒純靜音不會觸發 `insufficient_audio_activity`。
- **實際的 `RealtimeSTTSession` 端到端**（10 秒語音、照實際速度每 21 毫秒送一次）：連線 254 毫秒、第一段文字在第一段聲音送出後 378 毫秒、最後一次 commit 243 毫秒回來（停止到拿到最終文字 243 毫秒）；最終文字經過整理流程後沒有簡體字、有「台」、字典詞「Claude Code」拼對。
- **一般辨識（Scribe v3 上傳）**：目前送的所有欄位（`model_id=scribe_v3`、`language_code`、`secondary_language_codes`、`tag_audio_events`、`diarize`、`timestamps_granularity=none`、`no_verbatim`、重複的 `keyterms`）都被接受，HTTP 200、回 `text`，10 秒語音約 0.8–1.2 秒。不用改。
- **測試 key**：`GET /v1/user` 200，所以設定頁的「測試」會顯示成功；這把 key 是有權限範圍的（`GET /v1/models` 401），不影響辨識。
- 可以重跑：`Packages/ScriberCore/Tests/ScriberCoreTests/LiveElevenLabsTests.swift`，沒設環境變數時自動略過（要設 `SCRIBER_LIVE_ELEVENLABS_KEY_FILE`、`SCRIBER_LIVE_AUDIO_WAV`、`SCRIBER_LIVE_AUDIO_M4A`，測試本身不含 key 或路徑）。

#### 還沒驗證
- **真的麥克風、真的說話**：上面全部用合成語音；口音、背景噪音、中英夾雜的實際表現要實機試。
- **15 分鐘長錄音**：文件沒寫單次連線的時間上限（只有 `session_time_limit_exceeded` 這個錯誤），為了不花太多額度沒有實測。碰到上限會自動改用一般辨識，不會掉字，但那次就看不到後半段的即時文字。
- **網路很差時**的卡住判定（4 秒）和逾時（3 秒／8 秒）是估的，要看實際紀錄再調。
- 文件說 `keyterm_library` 只有在聽到可能的詞時才用；實測只確認了伺服器接受，沒確認效果。
- **計價**：即時辨識每小時 0.22 美元（一般 Scribe v3 是 0.20），用了個人字典再加每小時 0.08 美元（一般辨識加 0.05）。改用一般辨識的那次兩邊都會計費。

#### 之後做 iOS 版要注意
核心的 `RealtimeSTTSession` 只用 Foundation（`URLSessionWebSocketTask`），iOS 可以直接用，這一輪沒有接到 iOS：
- **主 App 在背景錄音**：鍵盤叫 App 錄音時 App 在背景，WebSocket 在背景能不能持續送、被系統暫停時怎麼辦，都要另外驗證；連線斷掉時要確保一樣改用上傳辨識（Mac 的做法可以照搬）。
- **鍵盤沒有空間顯示即時文字**，而且文字要從 App 傳到鍵盤（目前的 `SessionState` 只有最終結果），要另外設計顯示方式和傳遞頻率。
- **鍵盤內錄音**（實驗功能）在鍵盤程序裡，記憶體很緊，要注意連線和緩衝的用量。
- 錄音檔照舊要寫（改用上傳辨識時需要）。iOS 的錄音是 `CaptureBuffer`／`CaptureAssembler`，要在 16 kHz 樣本產生的地方同樣接一份給 session。

### 2026-11-22　第三輪：首次設定、首頁、兩種快捷鍵（Kazen 看完第一次實機畫面的意見）

Kazen 的意見：首次設定內容沒有垂直置中、按鈕過時（不要整條扁平的橘色長條）、API key 那一步清單被裁切又不能捲動、輔助使用的系統確認太長太嚇人；首頁只有一張小卡片浮在空白視窗裡、多一個工具列按鈕、側邊欄太擠。參考 VoiceInk 首頁的**結構**（大字省下的時間＋最近的逐字稿），不抄它的圖和字。

#### 兩種快捷鍵（`HotkeySelection`，有單元測試）
| | 組合鍵 | 單鍵 |
|---|---|---|
| 做法 | Carbon `RegisterEventHotKey` | `CGEventTap` |
| 權限 | 不需要 | 輔助使用 |
| 預設 | ⌥ Space（可在設定或「試一次」更改，至少要有 ⌘ ⌃ ⌥ 其中一個；F 鍵可以單獨用；esc 不能用） | 右邊的 Option（右 ⌘、右 ⌃、Fn 可選） |
| 說完 | 文字放進剪貼簿，浮動指示說「請按 ⌘V 貼上」 | 直接貼到游標處 |
| 變化 | 翻譯（組合鍵再加翻譯鍵，例如 ⌃⌥ Space）；說話改字只在有輔助使用時才有 | 跟之前一樣 |

- **自動切換**：沒有輔助使用時只註冊組合鍵。允許之後，等事件監聽真的開始運作才放掉組合鍵（中間不會有沒有快捷鍵的空檔）；監聽建立失敗時繼續用組合鍵，並提示「重新開啟 Scriber」。權限被收回時馬上改回組合鍵。
- **畫面一律顯示「現在真的能用的那個」**（`HotkeyRuntime`）：首頁問候語下的提示、試一次、設定的「現在使用」、選單列狀態列都跟著它。
- **不會默默衝突**：組合鍵用 exclusive 方式註冊，別的 App 或 macOS 已經用掉（例如 ⌘ Space 是 Spotlight）時註冊失敗，畫面寫「⌥ Space 已被其他 App 使用」並讓你換一組；另外比對系統快捷鍵表（例如 ⌃⌥ Space 是切換輸入法，註冊得上但不會觸發），一樣當作衝突。被佔用時每 10 秒再試一次（對方 App 可能關了）。實測（2026-11-22，macOS 27）：⌥ Space、⌃⌥ Space 都註冊得上；⌘ Space 回傳 `eventHotKeyExistsErr`。
- **esc 取消**：用組合鍵錄音時，只在錄音期間註冊 esc。
- 選單列：沒有輔助使用不算「需要處理」（圖示維持 `mic`），「請按 ⌘V 貼上」也不閃錯誤圖示；組合鍵被佔用或沒有麥克風權限才顯示 `mic.slash`。選單多一項「開啟自動貼上…」（沒開時才出現）。

#### 首次設定（新流程，640 × 620 固定視窗）
目標：一分鐘內開始說話，最重的權限放最後、而且是選用。
1. **歡迎**：自己畫的麥克風插圖（赤陶橘圓盤＋白色麥克風＋黑色墨線，跟 App 圖示同風格）、「歡迎使用 Scriber」、一句話、三個重點。主要按鈕「開始設定」。

3. **選擇語音辨識服務**：跟設定頁同一組引擎列（勾號、名稱、右邊直接設定 key）。
4. **試一次**：標題下用鍵帽顯示現在能用的快捷鍵（⌥ Space）。在這個視窗的輸入框說一句；沒有輔助使用時結果直接填進輸入框（在其他 App 則是放進剪貼簿按 ⌘V）。輸入框下方即時顯示「聆聽中…／整理中…／成功了」，缺麥克風、缺 key、快捷鍵被佔用時顯示那一個問題和修正按鈕；「換快捷鍵」就地開啟組合鍵設定。

版面：每一步的內容在頁尾上方的空間**垂直置中**，比視窗高時改成**捲動**（截圖檢查過 520 × 440 的極端尺寸，不會裁切也不會蓋到頁尾）。頁尾：左「上一步」、中間進度點（目前一步是長的橘色膠囊）、右邊一個按鈕；每個畫面同時只有一個醒目的按鈕（還沒完成的步驟，醒目的是步驟本身的按鈕，右下角只是安靜的「略過」）。Return 按醒目的那個，esc 回上一步。標題列透明、不顯示標題文字，內容延伸到標題列下。

### 2026-11-22　第四輪：設定頁的操作感、自訂快捷鍵、側邊欄上方空白

Kazen 跑了第三輪之後的意見：設定頁的控制項不順（橘色文字的彈出選單、搶眼的橘色「按鍵設定」、單選鈕散在整列、「現在使用」重複資訊，六列裡三種控制項樣式）；「設定 key」按鈕一直出現；單鍵應該可以自訂；側邊欄上方空太多。

- **原因**：之前整個視窗套了 `.tint(Theme.accent)`，在 macOS 26 以上會把彈出選單文字和 `.glass` 按鈕都染成橘色。現在拿掉，只有每個畫面唯一的主要按鈕（`.glassProminent`）和「開啟」狀態（開關、勾號、綠點）用顏色。
- **快捷鍵區塊**（每一列都是：左邊標題＋一行小字，右邊一個靠右的標準控制項）：
  1. **快捷鍵**：現在生效的那一個，用鍵帽顯示，旁邊一個「更改」。有輔助使用時是單鍵（小字「單鍵・說完直接貼上」），沒有時是組合鍵（「組合鍵・說完按 ⌘V 貼上」）。問題直接寫在小字（被佔用、還沒生效、🌐 鍵設定附「鍵盤設定」連結、F 鍵在筆電可能要按住 fn）。
  2. **操作方式**：分段控制「點一下｜按住說話」，小字寫目前的說明。
  3. **說話改字／翻譯**：標準彈出選單（不使用、Shift ⇧、Control ⌃、Option ⌥、Command ⌘），衝突時小字變成提示。
  4. 另一種快捷鍵收在展開列（有輔助使用時是「備用組合鍵」，沒有時是「單鍵快捷鍵」），一樣是鍵帽＋更改。
  拿掉「現在使用」那一列。
- **錄製快捷鍵**：按「更改」（或點鍵帽）→ 虛線框「按下想用的鍵…」，小字說明可以用什麼，esc 或「取消」離開；按到不能用的鍵時小字說原因、繼續等下一個鍵；設好顯示「已設定」。錄的時候全域快捷鍵暫停。
  - **單鍵**：任何修飾鍵、**左右都可以**（⌘ ⌥ ⌃ ⇧）、Fn／🌐、F1–F20。一般按鍵不行（「一般按鍵打字時會觸發，請用修飾鍵或 F 鍵」）；Caps Lock 不行（macOS 在硬體層切換大小寫，App 攔不住：「Caps Lock 會切換大小寫，不能用」）。
  - **組合鍵**：⌘／⌃／⌥（可加 ⇧）＋一個鍵，或單獨的 F 鍵；照舊檢查衝突。
  - 實作：`TriggerKey` 改成以實體按鍵（key code）為準的型別，存成短字串；第一版的 `rightOption`、`rightCommand`、`rightControl`、`fn` 原樣可讀。狀態機維持「乾淨的單按才算」：F 鍵是按下／放開事件，只有確定是 Scriber 的按壓（乾淨、而且代表聽寫或變化）才吞掉，⌘F5 這類照樣交給其他 App。新增 14 個測試（左右修飾鍵、Shift 當單鍵、F 鍵點按／按住／變化鍵／被當組合鍵時放行、打字中按 F 鍵、全部 29 個鍵與舊名稱的存讀）。
- **權限、自動貼上**：狀態是安靜的「● 已開啟／● 未開啟」（綠點、灰點，擋住使用時是橘點），只有需要處理時才出現按鈕（開啟…、允許、打開系統設定、重新開啟 Scriber）。安全輸入改成輔助使用那一列的小字。
- **辨識引擎列**：沒有 key 時右邊只有淡淡的「未設定」；滑過整列（或用鍵盤移到按鈕上）才浮現「設定 key」；**選中但沒有 key** 的那一列一直顯示（它需要處理）。有 key 的維持安靜的「已設定」選單。自訂引擎同樣處理。整列滑過時有淡底色、點一下就選取；VoiceOver 在列上有「設定 key」動作。

### 2026-11-22　第五輪：音訊設定（麥克風、提示音、錄音時的行為）

設定頁在「標點符號」和「一般」之間多一個 **音訊** 區塊，平常只有四列；不常改的提示音收在展開列裡。原本「一般」裡的「開始和結束時播放提示音」拿掉，舊值自動轉換（關 → 開始、結束都設成「無」；開 → 維持預設）。所有設定存在 Mac App 的 UserDefaults（`mac.audio.*`），每次錄音開始時重新讀，改了下一次就生效。

| 列 | 做什麼 |
|---|---|
| **麥克風** | 「跟隨系統（目前的裝置名）」或指定一個裝置。清單來自 Core Audio（有輸入聲道的裝置，名稱後加「內建／藍牙／USB／iPhone…」；隱藏裝置和系統自己建立的 `CADefaultDeviceAggregate` 不列），用 Core Audio 監聽即時更新，不需要重新整理按鈕。指定的裝置沒接上時清單裡顯示「名稱（未連接）」，標題下小字「未連接，錄音時改用系統預設」。旁邊的 **測試** 只在按下時開麥克風 5 秒，標題下顯示音量條；沒有麥克風權限時不出現（不會跳權限詢問），聽寫中不能按，開始錄音會先停掉測試。 |
| **錄音時靜音其他聲音** | 錄音期間把預設輸出裝置靜音，結束後恢復。 |
| **錄音時暫停媒體** ＋ **恢復播放**（立即／1／2／3／5 秒後，預設 1 秒，只在開啟時出現） | 錄音開始時暫停正在播放的音樂或影片，結束後只恢復被 Scriber 暫停的。這台 macOS 做不到時開關變灰，原因收在「?」。 |
| **提示音**（展開） | **開始**、**結束** 各自選「預設／無／自訂：檔名／選擇檔案…」，旁邊 ▶ 試聽；**音量** 滑桿（放開時存並試聽一次；兩個都「無」時不顯示）。收合時右邊顯示「預設／關閉／只有開始／只有結束／自訂」。 |

「?」：麥克風（跟隨系統、沒接上時怎麼辦）、藍牙耳機（用 AirPods 的麥克風會切到通話模式，錄音期間聽到的聲音和音質都變差）、測試、提示音（5 秒以內、音量相對於 Mac 的音量）。

#### 麥克風怎麼選（`InputEngine`、`InputDeviceResolver`）
- 指定的裝置以 Core Audio 的 UID 記住（拔掉再插回 UID 不變），裝置不在時偏好照樣保留，接回來的下一次錄音自動再用它。
- 每次錄音建立新的 `AVAudioEngine`，在讀格式、裝 tap、啟動之前，對輸入節點的 audio unit 設 `kAudioOutputUnitProperty_CurrentDevice`。不動系統的預設輸入，也不碰輸出節點。tap 改用 `format: nil`（節點自己的格式），裝置格式跟預期不同也不會觸發格式不符的例外。
- 指定的裝置有任何問題（沒接上、沒有輸入聲道、audio unit 拒絕、取樣率不一致、引擎起不來、啟動後 audio unit 不在那個裝置上）→ 這一次改用系統預設，原因寫進紀錄。第一次改用時浮動指示閃一下「改用預設麥克風」，之後裝置一直不在就不再提醒，直到它被用過一次或改了設定。
- 錄音中裝置變動：照舊重建引擎接著寫同一個檔；重建時指定的裝置還在就繼續用，不在就改用目前的預設。

#### 提示音
- 預設音檔照舊是 `Mac/Resources/Sounds` 的兩個檔（來源與 GPL-3.0 授權見那裡的 NOTICE.md，沒有加任何新音檔）。
- 自訂：選檔後先檢查（`AVAudioFile` 讀得出長度、`NSSound` 播得出來、10 MB 以內），超過 5 秒拒絕、超過 2 秒可以用但提醒「有 x 秒，可能太長」，然後複製到 `~/Library/Application Support/Scriber/Sounds/`（原檔搬走或刪掉也照常），換新檔時刪掉舊的。自訂檔不見了就播預設。
- 音量是 `NSSound.volume`，相對於系統音量（不會比系統音量大；輸出靜音時聽不到）。
- 結束提示音在麥克風停止**之後**、恢復音量**之後**才播；取消（esc、組合鍵中斷）一律不出聲。

#### 開始提示音的時機（決定）
量過預設的開始提示音：0.42 秒，兩個音，能量集中在前 0.25 秒（第二個音約在 0.18 秒）。要讓麥克風完全收不到，只有兩種做法，都不採用：
- **先播完再開麥克風**：要延後約 0.3 秒才開始收音，一按就講的人會掉第一個字。
- **丟掉開頭的 N 毫秒**：對著提示音說話的人一樣會掉第一個字。

採用的做法：**先叫提示音播放、緊接著開麥克風**（`NSSound.play()` 立刻返回，不增加任何延遲；引擎啟動的時間剛好蓋過第一個音的一部分），**錄到的聲音一點都不刪**。另外，提示音從喇叭出來時（內建喇叭、HDMI／DisplayPort 螢幕、AirPlay；耳機、藍牙、USB 不算），判斷「有沒有聲音」時忽略開頭等於提示音長度的那一段（最多 1 秒）。所以只錄到提示音、沒說話的那次會顯示「沒有聽到聲音」，不會送去辨識（避免多花一次費用和 Whisper 對雜音亂猜字）；有說話的那次，整段原封不動送出。代價：如果整句話短到完全落在開頭 0.4 秒內、之後都沒聲音，會被當成沒聲音（實際上幾乎不會發生）。紀錄裡同時寫 `peak` 和 `peakAfterCue`。

#### 錄音時靜音其他聲音（`OutputMuter`）
- 開始：提示音播完（長度＋0.08 秒，自訂的長音檔最多等 2 秒）才靜音，所以提示音聽得到；沒有開始提示音就立刻靜音。在提示音播完前就停止錄音的話，根本不會靜音。
- 做法：預設輸出裝置的靜音開關（主控制，沒有就每個聲道）；裝置沒有靜音開關才把音量設成 0、記下原本的音量。已經是靜音或音量 0 的裝置完全不碰，結束時也不會去「恢復」。兩種都沒有的裝置（部分 HDMI、USB）不處理，紀錄寫 `mute unsupported`。
- **改之前先寫下紀錄**（裝置 UID、方法、原本的值）到 UserDefaults 並立刻同步；恢復成功才刪掉。
- 恢復只還原「還是 Scriber 留下的樣子」的部分：錄音中使用者自己取消靜音或調大音量，就照使用者的。
- 恢復的是**當初靜音的那個裝置**（用 UID 找），不是現在的預設輸出（錄音中插上耳機也一樣）。
- 每一種結束方式都會恢復：正常結束、按 esc／選單取消、按住時按了別的鍵、麥克風起不來、最長 15 分鐘到了、麥克風中斷、系統睡眠、結束 App（含 `kill`、終端機 Ctrl-C：收到 SIGTERM／SIGINT 時走正常結束流程）。**當機或 `kill -9`**：下次開 App 第一件事就是讀紀錄、恢復聲音。被靜音的裝置剛好不在（例如藍牙喇叭關了）：紀錄留著，裝置回來（Core Audio 通知）、下一次錄音、或下次開 App 時再恢復。恢復失敗（OSStatus 不是 0）同樣保留、之後再試。
- 已知限制：App 當機後**沒有再打開**的話，要等下次開 App 才會恢復（開機自動開啟有打開時就是下次登入）。

#### 錄音時暫停媒體（研究與決定）
- macOS 沒有公開 API 能讀取或控制別的 App 的播放。系統的「正在播放」服務是私有的 MediaRemote。
- **macOS 15.4 起**，MediaRemote 只回應 bundle id 以 `com.apple.` 開頭的程序；直接在第三方 App 裡載入就拿不到東西（社群與 mediaremote-adapter 專案的紀錄；本機 macOS 27.3 實測，C 函式 `MRMediaRemoteGetNowPlayingApplicationPID` 在第三方程序裡回 0）。
- **模擬鍵盤的播放／暫停鍵**：不知道有沒有在播，而且是切換，沒在播時會反而開始播放。不採用。
- **採用**：用系統內建的 `/usr/bin/osascript`（Apple 簽署、bundle id `com.apple.osascript`）跑一小段 JavaScript for Automation，在**另一個程序**裡載入 MediaRemote：讀「正在播放的 App 是否在播、它的 bundle id 和 pid」，送明確的 **pause（1）／play（0）** 指令（從不送切換）。私有 API 的變動最多讓那個 osascript 失敗，不會讓 Scriber 當掉；任何失敗（載入不到、類別不在、逾時 4 秒、輸出不對）都當成「無法使用」。設定頁打開時先做一次唯讀檢查，做不到就把開關變灰、「?」寫原因。本機 macOS 27.3 用唯讀和不送指令的 dry 模式驗證過：讀得到正在播放的 App 與播放狀態，整段每次約 0.1–0.2 秒。
- 安全規則（都有單元測試）：只在 App 回報「正在播」時才送 pause，送完最多 1.2 秒內再讀一次確認；恢復時只對**同一個 App（bundle id＋pid）**、而且**當下沒在播**才送 play（在 osascript 裡送之前當場檢查），所以不會開始原本沒在播的東西。延遲期間又開始錄音：維持暫停、不重複暫停，最後只恢復一次。系統睡眠造成的取消不恢復；恢復的時間比預定晚 10 秒以上（Mac 睡過）也不恢復。結束 App 時立刻恢復。整個過程都不擋流程：結束錄音後辨識和貼上照常進行，恢復播放是之後的事。
- **沒有驗證**（不能在這台 Mac 暫停 Kazen 正在播的東西）：實際送出 pause／play 後各 App（Music、Spotify、Safari／Chrome／Arc 的影片）有沒有反應。有社群回報 macOS 26.1 能讀但送指令被擋、26.2 又可以；如果在 27 被擋，暫停不會發生，紀錄會看到 `paused(… confirmed=false)`，恢復時因為「已經在播」而略過，不會出錯。

#### 順序
- 開始：要求暫停媒體（非同步）→ 開始提示音 → 立刻開麥克風 → 提示音播完後靜音。
- 結束：麥克風停止 → 取消還沒發生的靜音 → 恢復音量 → 結束提示音（只有正常結束）→ 延遲後恢復播放。

#### 診斷紀錄（不記裝置名稱、檔名、播放內容；裝置只記 UID 的短雜湊 `dev#xxxxxx`）

### 2026-11-22　檔案轉錄（側邊欄「轉錄」）

把音檔或影片丟進來拿到逐字稿。分段、重試、時間戳、說話者、匯出的做法和限制寫在 `PRD.md` 第 11 節「檔案轉錄」，iOS 和 Mac 共用同一份核心；這裡只記 Mac 的部分。

- **轉錄頁**（`Mac/Features/Transcribe/`）：
  - 上方是虛線框的拖放區：沒有任何檔案時是大的（插圖、「把音檔或影片拖到這裡」、主要按鈕「選擇檔案…」），有檔案或逐字稿後縮成一條。整頁都可以放檔案，放上去時框變成赤陶色。可以一次放好幾個，會排隊一個一個做。
  - 拖放區下方一排：目前的辨識引擎（跟設定同一個）、語言選單、「時間戳」「說話者」兩個開關、「?」。不是 Scribe 時「說話者」是灰的。缺 key 時最上面一列「需要 Scribe v3 的 API key」＋「設定 key」；這時丟進來的檔案會先跳出填 key，填好就開始。
  - 「進行中」：每個檔案一張卡片（檔名、長度、「4／13 段・約 4 分鐘」、進度條、最新的幾行字（舊的往上淡出）、取消）。完成是「打開」，中斷是「繼續」，失敗寫原因：key／額度問題是「設定 key」或「重試」，檔案本身的問題（打不開、沒有聲音）不給重試；有段落失敗時寫出時間範圍和「重試失敗的段落」。「清除已完成」把做完的卡片拿掉（逐字稿還在）。
  - 「逐字稿」清單：標題、日期・長度・引擎（有缺漏時標出段數）、第一行內容；點一下打開；滑過出現拷貝、匯出（.txt／.md／.srt）、「…」（重新命名、刪除）。
  - 逐字稿畫面（同一頁裡）：返回（⌘[）、標題（雙擊改名）、日期・長度・引擎・字數；右上「拷貝」（⇧⌘C）、「匯出」選單（存檔視窗）、「…」（顯示時間戳、顯示說話者、重新命名、刪除）。內文是可選取的文字（`NSTextView`，幾小時的文字也不卡），時間戳和說話者標籤用較淡的字。
- **不需要輔助使用、不碰麥克風**，只要語音辨識的 API key。主視窗關掉轉錄照樣繼續（選單列 App 還在）；結束 App 後再開，未完成的檔案顯示「已中斷」，按繼續只做剩下的。
